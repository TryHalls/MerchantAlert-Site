# Manual first-user playbook

The first customers should be found through direct, respectful conversations with people who already own the Merchant Center problem. No paid acquisition, scraping, or automated spam is required.

## Ideal first conversations

Prioritise:

1. Shopify store owners with meaningful product visibility and a recurring Merchant Center workflow.
2. Ecommerce operators who already receive disapproval or limitation alerts but lack a reliable triage routine.
3. Small agencies that manage several Shopify stores and need a common health-check rhythm.

Avoid broad outreach to businesses that only need feed creation, catalog editing, bid management, or general SEO.

## Qualifying questions

Ask only what is needed to learn the workflow:

- How do you notice a new Merchant Center issue today?
- Who owns the first response when product visibility drops?
- Which issue types are expensive to discover late?
- Do clicks or impressions change how you choose what to fix first?
- What would make a weekly health check worth paying for?
- Would you try a manual pilot if the connection and permissions were clearly explained?

Never ask a prospect to send credentials, API keys, Merchant Center exports containing personal data, or customer information through an outreach channel.

## Short message template

> Hi — I’m exploring MerchantAlert, a very narrow tool for Shopify stores: it watches Google Merchant Center for new disapprovals, limitations, and issues, then prioritises what deserves attention. It is not a feed manager. I’m speaking with a few operators about how they catch these problems today. Would you be open to a 15-minute workflow chat? No login or data needed for the conversation.

## A useful call structure

1. Ten minutes: understand the current detection and triage workflow.
2. Three minutes: show the monitoring loop and example issue queue.
3. Two minutes: ask whether a manual, paid pilot would be useful and what success would mean.

Record only consented notes, keep them outside this public repository, and delete them when they are no longer needed for the validation decision.

## Weekly operating loop

- Contact a small, relevant set of potential users manually.
- Run conversations before adding features.
- Track only: conversation, problem confirmed, pilot interest, blocker, next action.
- Turn repeated language into copy improvements.
- Stop or change the message if the same audience does not recognise the problem.

The goal is not a large mailing list. The goal is one consenting pilot, then one paid pilot with a clear success criterion.
