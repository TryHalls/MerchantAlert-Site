# First pilot plan

This is the smallest commercial path from public validation to a first paid MerchantAlert pilot. The owner does not want calls, demos, or personal prospect conversations, so the process is asynchronous by default.

## Target

Find one Shopify store owner, ecommerce operator, or small agency that:

- already manages Google Merchant Center;
- has experienced disapprovals, limitations, or issue discovery too late;
- can describe the current detection and triage workflow in writing;
- is willing to test a narrow monitoring product without asking for a feed manager.

## Pilot offer

**Working offer:** one monitored store, manual onboarding, issue detection/history, impact-aware prioritisation, and email-oriented alerts for one validation period.

The offer is not a promise that Google will approve products, restore traffic, or resolve issues automatically. Final duration, price, taxes, refund rules, support expectations, and data-processing terms require owner approval before payment is requested.

## Asynchronous qualification

Ask in writing:

1. How do you notice a new Merchant Center issue today?
2. Which issue types are most expensive to discover late?
3. Who owns the first response when product visibility changes?
4. Would clicks/impressions change the order in which you fix issues?
5. Would you test a read-only monitoring layer if no call were required?
6. At what monthly price would the pilot stop being an obvious experiment?

Do not ask prospects to send passwords, Merchant Center exports containing personal data, API keys, OAuth secrets, service-account files, or customer data.

## Success criteria

Agree in writing on one or two observable outcomes before onboarding, such as:

- a newly introduced issue is detected during the pilot;
- the operator receives a useful alert without checking the dashboard first;
- the issue queue makes the first action clearer than the existing workflow;
- the operator can explain whether the product is worth renewing.

Do not use traffic recovery or Google approval as a guaranteed success metric; MerchantAlert is a monitoring layer, not Google's decision-maker.

## Conversion path

```text
permissioned public validation
  -> written pilot interest
  -> asynchronous qualification
  -> one agreed success criterion
  -> owner completes legal/fiscal/payment gates
  -> controlled onboarding
  -> paid renewal decision
```

No payment should be requested until the owner has chosen the contracting identity, currency, tax treatment, payment method, refund/cancellation rules, privacy terms, and support contact.

## Owner handoff

The owner should only be required for actions that cannot be delegated safely: identity, legal/fiscal decisions, acceptance of terms, account login/2FA, payment setup, domain purchase, and secrets.

Calls, demos, and personal prospect conversations are not required by this plan.
